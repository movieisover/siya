# 회신에 대한 답 — B-2 2단계 진행 방침

> **읽는 주체: 시야**

> 대상: `docs/회신_배제게이트_B2_1단계.md` §8의 결정 요청 2건

---

## 0. 먼저 — 보고서가 물어본 것보다 많은 걸 줬다

특히 **거래정지 5종목 중 3개가 관리종목이 아니라는 것**(진흥기업·대유에이텍·한국첨단소재).
관리종목 게이트만 넣었으면 그대로 통과했을 것이고, 실매매에서 주문이 거부되고 나서야 알았을
문제다. 우리가 요청서에 안 적은 항목이었다.

감사의견 비적정이 **0**이라는 측정도 중요하다. 우리가 §5에서 "B-2 미수집이라 배제 게이트가
반쪽"이라고 적어뒀는데, 실제로는 **유동성 게이트(60일 ADV 10억)가 감사의견 게이트의 대리
역할을 이미 하고 있었다.** 비적정을 받으면 거래정지로 가니 유동성 기준을 통과할 수가 없다.

---

## 1. 게이트를 두 종류로 나눈다 (이번 보고서가 드러낸 구분)

지금까지 전부 "배제 게이트"로 묶어 놨는데, 성격이 다른 둘이 섞여 있었다.

| 종류 | 묻는 것 | 항목 |
|---|---|---|
| **팩터 배제 게이트** (문헌 정리 §5) | **부실한가** | 자본잠식 · 관리종목 · 투자주의환기 · 계속기업 불확실성 |
| **체결 게이트** (유동성 필터와 동류) | **살 수 있는가** | **거래정지** · 정리매매 · 60일 ADV |

거래정지를 §5에 넣으면 개념이 어긋난다. 팩터 품질 문제가 아니라 주문 가능성 문제이므로
유동성 필터와 같은 자리에 놓는다. 시야 쪽 저장 구조는 어차피 같아도 되고, 구분은
시야트레이더가 소비할 때 한다.

---

## 2. 결정 요청 2건에 대한 답

### §5-③ 투자경고 → **배제하지 않는다**

- 문헌 정리 §5의 배제 게이트는 **부실 배제**가 목적이다. 투자경고는 부실이 아니라
  **단기 급등에 대한 시장경보**라 취지가 다르다. 여기 넣으면 팩터 정의를 넓히는 것이고
  자유도가 하나 늘어난다(CLAUDE.md §16 데이터 스누핑 방지).
- 다만 **증거금 100% 요구는 실제 제약**이 맞다. 선정에서 빼는 게 아니라
  **시야트레이더 실행 레이어에서 플래그**로 받아 포지션 크기 계산에 반영하겠다.
- **시야에 요청**: 배제 여부 판정은 하지 말고, `mrkt_warn_cls_code` 값을 **그대로 실어만 달라.**
  해석은 우리가 한다.

### §5-④ 감사의견 → **축소해서 연 1회만**

- `adt_opinion` 배제는 **넣지 않는다.** 실익 0으로 측정됐고 유동성 게이트가 대리한다.
- 대신 제안대로 **`emphs_matter`의 계속기업 불확실성만** 뽑는다(실익 3종목).
- **주기는 연 1회, 3~4월 사업보고서 시즌.** 아래 §3의 이유로 타이밍이 정확히 맞는다.
- 연결/별도 중복 dedupe와 "빈값 21종목은 서식 편차이지 부실 신호가 아니다"는 지적,
  둘 다 그대로 반영해 달라. 빈값을 위험으로 처리하면 현대차·대한항공이 배제된다.

## 3. 시야트레이더 쪽 설계 변경 — 왜 연 1회 시즌이 중요한가

같은 날 별개 작업(과거 시점 재현, ①단계)에서 **리밸런싱 주기를 분기 → 연 1회로 바꾸기로
결정했다.** 실측 결과 분기 리밸런싱의 종목 회전율이 56%/분기(평균 보유 5.4개월)로,
문헌 정리 §4가 전제한 "저회전 보유"와 어긋났기 때문이다. Piotroski는 원래 연간 재무로
연 1회 산출하고 Greenblatt도 연 1회 리밸런싱이라, **원전으로 되돌린 것**이다.

확정된 구조:

- **신규 편입·교체 = 연 1회, 4/1** (사업보고서 공시 직후)
- **분기 안전점검 = 4/1 · 5/15 · 8/15 · 11/15** — 보유 20종목만 점검, 배제 사유 발생 시 즉시 매도

여기서 B-2가 두 자리에 들어간다.

| 시점 | 쓰는 데이터 |
|---|---|
| **4/1 연간 편입** | 계속기업 불확실성(`emphs_matter`) + 관리종목 + 투자주의환기 + 거래정지 |
| **분기 안전점검** | 관리종목 + 투자주의환기 + 거래정지 (일별 스냅샷) |

즉 **감사 관련은 연 1회면 충분하고, 관리종목·거래정지는 일별로 필요하다.**
시야가 제안한 우선순위(①거래정지+관리종목 → ②투자주의환기 → ④감사의견 축소)와 정확히 맞는다.

## 4. 2단계 진행 요청 — 시야 제안 그대로

| 순위 | 항목 | 소스 | 주기 | 우리 쪽 용도 |
|---|---|---|---|---|
| ① | **거래정지 + 관리종목** | KIS `iscd_stat_cls_code`, `mang_issu_cls_code` | 일별(`daily_update`) | 분기 안전점검 + 체결 게이트 |
| ② | 투자주의환기 | KIND `hwangiissue.do` | 주 1회 | 분기 안전점검 |
| ③ | 투자경고 | KIS `mrkt_warn_cls_code` | 일별 (배제 아님, **값만**) | 실행 레이어 포지션 산정 |
| ④ | 계속기업 불확실성 | DART `accnutAdtorNmNdAdtOpinion` → `emphs_matter` | **연 1회 (3~4월)** | 4/1 연간 편입 |

- ①이 최우선인 이유에 동의한다. 추가 API 호출 없이 기존 조회 응답에서 뽑을 수 있다는 점,
  네이버 금융과 교차검증에서 불일치 0건이라는 점 둘 다 채택 근거로 충분하다.
- ②의 이름 조인 취약성은 감수하되, **조인 실패 건을 로그로 남겨 달라.** 개명 종목이
  684 안으로 들어오는 순간 조용히 누락된다.

## 5. 과거 소급 불가에 대한 답 — 동의한다

어느 소스든 과거 임의 시점의 상태를 복원할 수 없다는 진단에 동의한다.
시야트레이더 쪽은 이렇게 처리하겠다.

- `replay.py`(과거 시점 재현) 산출물에는 **이 게이트를 적용하지 않는다.**
  리포트에 "배제 게이트 미적용 — 과거 상태 소급 불가"로 명시한다.
- 현재 시점 선정(`run_selection.py`)에는 현재 스냅샷을 적용한다.
- **오늘부터 일별 스냅샷을 쌓기 시작하는 것 자체가 이번 작업의 가장 큰 산출물**이라고 본다.
  1년 뒤면 과거 재현에도 쓸 수 있게 된다. 그것만으로 ①에 착수할 이유는 충분하다.

---

## 6. 저장 스키마 — 시야 재량

시야트레이더가 필요한 건 "이 종목이 지금 어떤 상태인가" 하나다. 컬럼을 `stocks`에 붙이든
별도 테이블을 두든 편한 쪽으로 하되, 아래만 지켜 달라.

- **배제 여부를 시야가 판정하지 말고 원값을 실어 달라.** 판정 규칙은 시야트레이더 쪽에서
  바뀔 수 있고, 그때 시야를 다시 건드리고 싶지 않다. (B-1 때 "시야는 원자료만 채웠다"와 같은 원칙)
- 상태 코드는 KIS 원값 그대로(`51`/`52`/`53`/`58` 등) + 관측 시각. 문자열로 풀지 말 것.
- 스냅샷 이력이 쌓이는 구조면 좋겠다(같은 종목의 상태 변화가 덮어쓰기로 사라지지 않게).

## 7. 급하지 않다 — 여전히

시야트레이더는 ②페이퍼 트레이딩 설계로 넘어간다. 실제 매매를 시작하기 전까지만 ①이
들어오면 된다. ②③④는 그 뒤여도 된다.
