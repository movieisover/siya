# 회신 — 2023·2024 분기 재무 백필 완료 (B-3)

> **읽는 주체: 시야트레이더**
> 핸드오프(`docs/핸드오프_분기백필_B3.md`) §5에 대한 회신.

## 0. 결론

**2023 Q1~Q3, 2024 Q1~Q3 분기행 백필 완료** (2026-08-25~27, DART 한도 3일 분할).
저장 형식·단위·누적 기준·6컬럼 모두 기존 분기행과 동일. **전년 TTM 축이 생겨 F-score ③⑧⑨가 살아난다.**
백필 완료 후 시야트레이더는 코드 수정 없이 `run_selection.py` 재실행 → `delta_basis='ttm'` 자동 승급.

## 1. 커버리지 (§5-①)

**분기별 행 수** (2023·2024, 백필 후):

| 연도 | Q1 | Q2 | Q3 |
|---|---|---|---|
| 2023 | 2,214 | 2,252 | 2,341 |
| 2024 | 2,413 | 2,461 | 2,471 |

- 총 분기행 14,152 / 채움률 **94.5%** (14,152 / 14,973 = FY 보유 종목 × 6조합 상한 대비).
- 2024 > 2023은 그사이 신규 상장분. Q1 < Q2 < Q3 서열은 분기 갈수록 제출 종목 누적(정상).

**6컬럼 NOT NULL 비율** (2023·2024 분기 백필분 기준):

| 컬럼 | 채움률 |
|---|---|
| `cfo` | 99.9% |
| `cash_and_equiv` | 99.4% |
| `current_assets` | 98.7% |
| `current_liabilities` | 98.5% |
| `gross_profit` | 92.3% |
| `cost_of_sales` | 90.9% |
| (`net_income_owners`) | 99.6% |

**B-1(연간 cfo 99.7%, gross_profit 90.2%)과 서열·수치가 정합.** NULL이 `매출총이익/원가 > 유동구분 > 현금성 > CFO` 순으로 갈리는 패턴이 연간·2025분기·2023~2024분기 **세 기간 모두 동일** — 업종 특성(금융·순수서비스의 매출원가 부재)이 그대로 재현됐다. 데이터 품질 문제가 아니라 팩터 적용 가능 업종의 구조다.

## 2. 누적 기준 동일 확인 (§5-②)

**동일하다.** 2023·2024도 `thstrm_add_amount`(누적) 기준으로 저장됐다: Q1=3개월 / Q2=6개월 누적 / Q3=9개월 누적. B-1·2025 분기와 같은 `extract_financials(df, cumulative=True)` 경로를 그대로 탔다. 기간 정의가 섞이지 않았으므로 전년 TTM 공식(`FY2024 − 2024Q2누적 + 2025Q2누적`)이 당해 TTM과 동일 규칙으로 성립한다.

---

## 3. 계정 태그 / 매출총이익 산출 경로 (§5-③)

**결론: `gross_profit` 값은 신뢰 가능하되, "직접 태그 vs 계산 유도"의 비율은 시야 DB만으로는 셀 수 없다.**

`financials_common.extract_financials`의 산출 경로는 B-1과 동일하다: `ifrs-full_GrossProfit` 직접계정 우선 → 없으면 `revenue − cost_of_sales` 계산 폴백. 2023·2024 백필도 같은 코드 경로를 탔다.

실측(2023·2024 분기행 14,152 기준):

| 구분 | 행 수 | 해석 |
|---|---|---|
| `gross_profit` 있고 `cost_of_sales` NULL | 205 (1.4%) | **직접계정으로만** 채워진 행 (매출원가가 없어 계산 폴백은 애초에 불가) |
| `gross_profit`·`cost_of_sales` 둘 다 있음 | 12,860 | 직접계정 또는 계산 폴백 — DB만으로는 구분 불가 |
| `cost_of_sales` 있는데 `gross_profit` NULL | **0** | 폴백 체인에 구멍 없음 (매출원가가 있으면 매출총이익은 항상 채워짐) |

- **폴백 발동 횟수는 사후 집계가 불가능하다.** 폴백 조건이 `gross_profit is None and revenue is not None and cost_of_sales is not None`이라, 폴백으로 채워진 행은 반드시 `cost_of_sales`를 갖는다 → 직접계정으로 채워진 행과 컬럼 구성이 동일해 사후 구분이 안 된다. (참고: 둘 다 있는 12,854행 중 `gross_profit == revenue − cost_of_sales`가 성립하는 행은 6,590으로 절반 수준 — 나머지는 직접계정 값이 단순 차감과 다르다는 뜻이라, 직접계정이 폭넓게 쓰였다는 방증이다.)
- 비율이 꼭 필요하면 **수집기에 폴백 카운터를 넣고 재수집**해야 한다(현재 로그에도 카운터 없음). 이번 범위 밖.
- **시야트레이더 함의**: 어느 경로든 `gross_profit`의 정의(매출 − 매출원가)는 동일하므로 총이익성 팩터에는 영향이 없다. 경로 구분이 필요한 분석이라면 위 카운터 작업을 별건 요청할 것.

## 4. 정정공시 취급 — 룩어헤드 한계 (§5-④)

**시야 파이프라인에 정정 여부 플래그는 없다.** DART `finstate_all`은 조회 시점 기준 최신값을 반환하므로, 백필된 2023·2024 분기는 **당시 최초 공시 원본이 아니라 정정 반영 후 값**일 수 있다. 시야는 이를 그대로 upsert하며, "이 행이 원본인지 정정본인지" 구분하는 수단이 없다.

- **과거 시점 재현(`--as-of`)에서 미세한 룩어헤드**가 된다: 2024-11-20 시점을 재현해도, 그 이후 정정된 값이 들어가 있을 수 있다.
- 시야트레이더 쪽에서 이를 구분할 방법은 현재 없다. **리포트에 한계로 명시**하는 것을 권한다.
- 정정 이력이 필요하면 DART 별도 API(정정공시 목록)를 별건으로 요청해야 한다(이번 범위 밖).

## 5. skip 종목 수와 사유 (§5-⑤)

**총 344종목이 완전히 채워지지 않았다** (2023·2024 6조합 기준):

| 구분 | 수 | 사유 |
|---|---|---|
| 미착수(분기재무 없음) | 72 | DART에 그 종목의 분기보고서 자체가 없음(SPAC·특수법인·부실주) |
| 일부만 채움 | 272 | 반기·연간만 제출하고 분기(Q1·Q3)는 생략하는 중소형주 |

- 추가로 FY2023·2024 둘 다 없는 210종목은 애초에 조회 대상에서 제외(그 해 미상장 → 헛콜 방지).
- 이들은 **누락이 아니라 원본 부재**다. 특히 272종목은 Q2(반기)는 있으나 Q1·Q3가 DART에 없다.

> ⚠ **`--resume` 수렴 특성 (시야트레이더가 알 필요는 없지만 참고)**: 재개 판정이 "대상 6조합 전부 채움" 기준이라, 분기를 부분 제출하는 272종목은 6조합을 영원히 못 채워 매 재개마다 대상으로 재선정된다(→ 무한 헛콜). 따라서 백필 종료는 "재개 대상 0"이 아니라 "새로 채운 것 없음(성공 0, 건너뜀만)"으로 판정했다. 이건 수집 측 운영 이슈이며 데이터 정합성과는 무관하다.

**시야트레이더 함의**: 전년 TTM 계산 시 이 344종목(특히 Q1·Q3 부재 272종목)은 **Q2(반기) 기반 계산은 되지만 Q1·Q3 기반은 불가**하다. B-1 회신 §6-3의 NULL 정책(정의 불가는 0이 아님)이 그대로 적용된다 — 폴백 체인(전년 TTM → FY vs FY → 계산불가)에서 자연히 하위 단계로 내려간다.
