## 앱 개요

- **앱 이름**: 시야 (Siya)
- **플랫폼**: PC 앱 (Tauri + React)
- **분석 방식**: Top-down + Bottom-up 병행

### 분석 방식

| 모드 | 접근법 | 예시 |
|------|---------|------|
| 테마 분석 모드 | Top-down | "지금 뜨는 테마가 뭐지?" → AI/반도체 테마 → 관련 종목 분석 |
| 스크리너 모드 | Bottom-up | "재무 좋은 종목 찾아줘" → ROE/PBR 필터 → 종합점수 정렬 |

### 1-2. 시장 현황 (KOSPI / KOSDAQ / 환율)

**위치:** 상단 헤더 또는 좌측 패널 상단

**데이터 소스:** pykrx, FinanceDataReader

**업데이트 방식:**
- 앱 실행 시 자동으로 최신 데이터 수집
- 새로고침 버튼 클릭 시 갱신

**데이터 기준:**

| 상황 | 표시 데이터 | 변동률 기준 |
|------|------------|------------|
| 장중 (09:00~15:30) | 전일 종가 | 전전일 종가 대비 등락률 (%) |
| 장 마감 후 (15:30~) | 당일 종가 | 전일 종가 대비 등락률 (%) |
| 휴장 / 주말 | 최근 거래일 종가 | 직전 거래일 대비 등락률 (%) |

> 💡 변동률 = (기준일 종가 - 직전 거래일 종가) / 직전 거래일 종가 × 100
>
> ⚠️ 실시간 데이터는 유료 API 필요 → 현재 스코프 외

**실시간 데이터 옵션 (향후 업데이트용 참고):**

| 방법 | 실시간 | 비용 | 현실성 |
|------|--------|------|---------|
| 현재 (pykrx 등) | ❌ 종가만 | 무료 | ✅ |
| 한국투자증권 오픈API | ✅ | 무료 (계좌 필요) | ✅ 충분히 가능 |
| KRX 직접 계약 | ✅ | 수백만원+ | ❌ |

**나중에 실시간으로 전환할 때:**
```
현재:  pykrx/FinanceDataReader → Supabase DB → 앱
향후:  한국투자증권 API       → Supabase DB → 앱
                ↑
        이 수집 모듈만 교체 (DB/앱 수정 불필요)
```

## 2. 테마 분석 모드 (Top-down)

**컨셉:** 테마별 시그널을 감지하고 신뢰도를 계산하여 투자 참고 정보 제공
→ "지금 뜨는 테마가 뭐지?" → 관련 종목 분석

### 2-1. 좌측 패널: 테마 목록

**테마 목록 (20개)**

| 카테고리 | 테마 |
|----------|------|
| 첨단기술 | AI/반도체, 로봇/자동화, 우주항공, 양자컴퓨팅 |
| 에너지/소재 | 2차전지, 신재생에너지, 수소경제, 희토류 |
| 바이오/헬스 | 바이오/제약, 의료기기, 디지털헬스, 고령화/실버 |
| 산업/방산 | 방위산업, 조선/해운, 건설/인프라, 원자력 |
| 금융/소비 | 금융/핀테크, 게임/엔터, 리츠/부동산, 화장품/K뷰티 |

**테마 카드 표시 정보:**
```
테마명 / 신뢰도 등급 (HIGH/MEDIUM/LOW) / 방향예측 아이콘
```

### 2-2. 테마 시그널 감지 (3가지)

| 시그널 | 측정 방법 | 데이터 소스 |
|--------|----------|------------|
| 거래량 급증 | 테마 내 종목 평균 거래량 (20일 평균 대비 증가율) | pykrx |
| 기관/외국인 매집 | 테마 내 종목 기관+외국인 순매수 합계 (5일 누적) | pykrx |
| 동반 상승 | 테마 내 종목 중 상승 종목 비율 | pykrx |

### 2-3. 신뢰도 계산 로직

**신뢰도 점수 = 거래량(30점) + 수급(50점) + 동반상승(20점)** (만점 100점)

> 수급에 가장 높은 가중치 — 기관/외국인 움직임이 테마 지속성의 핵심 지표

#### 거래량 급증 점수 (30점 만점)

| 거래량 증가율 (20일 평균 대비) | 점수 |
|-------------------------------|------|
| +50% 미만 | 0점 |
| +50% ~ +100% | 10점 |
| +100% ~ +200% | 20점 |
| +200% 이상 | 30점 (만점) |

```
거래량 점수 = min((증가율% - 50) / 5, 30)
```

#### 수급 점수 (50점 만점) — 가장 중요

| 순매수 합계 (5일 누적) | 점수 |
|-----------------------|------|
| 순매도 (음수) | 0점 |
| 0 ~ +100억 | 10점 |
| +100억 ~ +300억 | 20점 |
| +300억 ~ +500억 | 35점 |
| +500억 이상 | 50점 (만점) |

```
수급 점수 = min(max(순매수억 / 10, 0), 50)
```

#### 동반상승 점수 (20점 만점)

| 상승 종목 비율 | 점수 |
|---------------|------|
| 50% 미만 | 0점 |
| 50% ~ 60% | 5점 |
| 60% ~ 70% | 10점 |
| 70% ~ 80% | 15점 |
| 80% 이상 | 20점 (만점) |

```
동반상승 점수 = min(max((상승비율% - 50) × 0.67, 0), 20)
```

#### 신뢰도 등급 분류

| 등급 | 점수 범위 |
|------|----------|
| LOW | 0 ~ 39점 |
| MEDIUM | 40 ~ 69점 |
| HIGH | 70 ~ 100점 |

#### 종합 예시: AI/반도체 테마

```
거래량: +150% → 20점
수급: +420억 → 42점
동반상승: 75% → 15점

신뢰도 점수 = 20 + 42 + 15 = 77점 → HIGH
```

### 2-4. 방향예측 (단순화 버전)

> ⚠️ AI 예측이 아닌 **시그널 기반 단순 판단**입니다.

| 조건 | 표시 |
|------|------|
| 신뢰도 HIGH **AND** 순매수 > 0 | ⬆ 상승 가능성 높음 |
| 신뢰도 MEDIUM **AND** 순매수 > 0 | ↗ 상승 가능성 있음 |
| 신뢰도 LOW **OR** 순매수 ≤ 0 | — 관망 |

**주의사항:**
- 이 표시는 멀티에이전트 AI 예측이 아님
- 시그널 데이터를 조합한 단순 판단
- 투자 참고용으로만 활용 (면책 문구 필수 표시)

### 2-5. 중앙 패널: 테마 내 종목 리스트

테마 클릭 시 → 해당 테마에 속한 종목들을 중앙 패널에 표시

각 종목 카드: `종목명 / 종목코드 / 등락률 / 수급(순매수) / 종합점수`

### 2-6. 타이밍 지표 (RSI/MACD)

**컨셉:** 신뢰도(테마의 힘)와 별도로, "지금 진입해도 되는가?"를 판단하는 보조 지표
→ 신뢰도와 역할 분리: 신뢰도 = 테마가 살아있나? / 타이밍 = 지금 들어가도 되나?

**데이터 소스:** TradingView-Screener (RSI, MACD 제공)

#### RSI 기반 판단 (테마 과열도)

테마 내 종목들의 **RSI 14일 기준 평균값** 사용:

| 테마 평균 RSI | 판단 |
|---|---|
| 70 이상 | 과열 (과매수 구간) |
| 30~70 | 중립 |
| 30 이하 | 저점 (과매도 구간) |

#### MACD 기반 판단 (추세 방향)

테마 내 종목 중 **MACD 골든크로스(MACD > Signal) 비율**:

| 골든크로스 비율 | 판단 |
|---|---|
| 60% 이상 | 상승 추세 |
| 40~60% | 혼조 |
| 40% 미만 | 하락 추세 |

#### 타이밍 종합 등급

RSI + MACD를 조합하여 3단계로 분류:

| 조건 | 타이밍 표시 | 의미 |
|---|---|---|
| RSI < 70 **AND** 골든크로스 ≥ 60% | 🟢 진입 적기 | 추세 상승 중이면서 아직 과열 아님 |
| RSI ≥ 70 **OR** 골든크로스 < 40% | 🔴 과열/하락 주의 | 과열이거나 추세 꺾임 |
| 그 외 | 🟡 관망 | 혼조 상태 |

#### 테마 카드 표시 예시

```
┌─────────────────────────────┐
│  AI/반도체                    │
│  신뢰도: HIGH (77점)          │  ← 기존 (거래량+수급+동반상승)
│  방향예측: ⬆ 상승 가능성 높음   │  ← 기존
│  타이밍: 🟢 진입 적기          │  ← 새로 추가
│  (RSI 58 | MACD 골든크로스 72%)│
└─────────────────────────────┘
```

#### 신뢰도 × 타이밍 조합 해석

| 신뢰도 | 타이밍 | 해석 |
|--------|--------|------|
| HIGH | 🟢 진입 적기 | 가장 좋은 조합 — 테마 강하고 타이밍도 좋음 |
| HIGH | 🔴 과열/하락 주의 | 테마는 강한데 과열 — 조심 |
| HIGH | 🟡 관망 | 테마 강하지만 추세 혼조 — 지켜보기 |
| LOW | 🟢 진입 적기 | 추세는 좋은데 테마 힘 약함 |
| LOW | 🔴 과열/하락 주의 | 약한 테마 + 나쁜 타이밍 |

### 설계 원칙

- 신뢰도 계산은 **pykrx 무료 데이터**만으로 가능
- 방향예측은 AI 예측이 아닌 **시그널 기반 단순 판단**으로 표현
- 타이밍 지표는 **TradingView-Screener** 데이터 사용 (RSI, MACD)
- 신뢰도(테마의 힘)와 타이밍(진입 시점)은 **독립적으로 판단** → 사용자가 두 축으로 의사결정
- 테마-종목 매핑 DB는 Phase 2에서 구축 예정

## 3. 스크리너 모드 (Bottom-up)

**컨셉:** 사용자가 직접 필터를 조합해서 원하는 종목을 추출하는 화면
→ "재무 좋은 종목 찾아줘" → 필터 + 종합점수 정렬

### 3-1. 좌측 패널: 필터 설정

**기본 필터 (버튼형)**

| 필터 | 옵션 |
|------|------|
| 시장 | 전체 / KOSPI / KOSDAQ |

**지표 필터 (슬라이더형)**

| 지표 | 기본값 | 방향 |
|------|--------|------|
| PER | 0 < PER ≤ 15 | 낮을수록 저평가 |
| PBR | PBR ≤ 1.5 | 낮을수록 저평가 |
| ROE | ROE ≥ 10% | 높을수록 수익성 좋음 |
| 부채비율 | ≤ 100% | 낮을수록 안전 |
| 배당수익률 | ≥ 0% (제한 없음) | 높을수록 배당 매력 |

> 💡 기본값 = 추천 종목 1단계 필터와 동일 (배당수익률은 기본 0%로 제한 없음)
> → 스크리너 처음 열면 추천 풀에서 시작
> → 사용자가 슬라이더 조정 시 WHERE 조건만 변경 (단순 DB 쿼리)

### 3-2. 종합 점수 계산 (추천 로직)

**컨셉:** 고품질·저평가 + 재무 개선 중인 종목 발굴
→ "남들이 아직 못 본 가치를 먼저 보는 것"이 시야의 핵심

#### 1단계 — 자격 필터 (통과/탈락)

```
ROE ≥ 10%              수익성이 있는 기업만
PBR ≤ 1.5              저평가 상태인 기업만
PER > 0                 적자 기업 제외 (PER=0은 탈락)
PER ≤ 업종 평균 × 1.2  업종 내 상대적 저평가만 통과
부채비율 ≤ 100%        재무적으로 안전한 기업만
```

> **PER 주의사항**
> - PER = 0.00 → 적자 기업 (데이터 오류 아님) → 1단계 탈락
> - PER 이상 고값 (예: 1,000+) → 일시적 이익 급감 → 이상치 처리 필요
> - PER 비교는 절대값보다 **업종 평균 대비 상대값** 사용

#### 2단계 — 점수 계산 (후보 종목 줄세우기)

**종합 점수 = 품질(50점) + 밸류에이션(20점) + 개선(30점)** (만점 100점)

##### 품질 점수 (50점 만점) — 수익성 평가

| 항목 | 배점 | 계산식 | 설명 |
|------|------|--------|------|
| ROE | 20점 | `min(ROE × 1, 20)` | ROE 20% = 20점 만점 |
| ROA | 15점 | `min(ROA × 1.5, 15)` | ROA 10% = 15점 만점 |
| 영업이익률 | 15점 | `min(영업이익률 × 1, 15)` | 영업이익률 15% = 15점 만점 |

> 예시: 삼성전자 (ROE 15.2%, ROA 8.5%, 영업이익률 12.3%)
> → 15.2 + 12.75 + 12.3 = **40.25점** / 50점

##### 밸류에이션 점수 (20점 만점) — 저평가 정도

| 항목 | 배점 | 계산식 | 설명 |
|------|------|--------|------|
| PBR 점수 | 10점 | `max(10 - (PBR × 5), 0)` | PBR 낮을수록 고득점 (PBR 0.5 = 7.5점) |
| PER 상대점수 | 10점 | `max(10 - (PER/평균PER × 5), 0)` | 평균 대비 저평가일수록 고득점 |

> 예시: 삼성전자 (PBR 1.42, PER 12.3, 테마평균 PER 15.0)
> → (10-7.1) + (10-4.1) = 2.9 + 5.9 = **8.8점** / 20점

##### PER 상대점수 — 평균 PER 계산 기준

| 모드 | 평균 PER 기준 | 설명 |
|------|-------------|------|
| 테마 분석 모드 | 선택한 테마 내 평균 PER | 사용자가 "AI/반도체" 선택 → 해당 테마 종목들의 평균 |
| 스크리너 모드 (전체) | 전체 시장 평균 PER | 테마 필터 없이 전체 검색 시 |

**평균 PER 계산 시 이상치 제외:**
```
유효 PER = 0 < PER ≤ 100 인 종목만 포함

제외 대상:
- PER ≤ 0 (적자 기업)
- PER > 100 (일시적 이익 급감으로 왜곡된 값)
```

> 💡 종목은 여러 테마에 **중복 소속 가능** (예: 삼성전자 → AI/반도체, 양자컴퓨팅)
> → 테마 분석 모드에서는 선택한 테마 기준으로 상대점수 계산

**PBR 구간별 점수:**
- PBR 0.5 이하 → 7.5점+
- PBR 1.0 → 5점
- PBR 1.5 → 2.5점
- PBR 2.0+ → 0점

##### 개선 점수 (30점 만점) — 재무 개선 추세

| 항목 | 배점 | 계산식 | 설명 |
|------|------|--------|------|
| ROE 개선 | 12점 | `min(max(ROE변화 × 2, 0), 12)` | 전년 대비 +6%p = 12점 만점 |
| 영업이익률 개선 | 12점 | `min(max(영업이익률변화 × 2, 0), 12)` | 전년 대비 +6%p = 12점 만점 |
| PBR 하락 | 6점 | `min(max(PBR하락폭 × 10, 0), 6)` | 전년 대비 -0.6 = 6점 만점 |

> 예시: 삼성전자 (ROE +2.1%p, 영업이익률 +1.5%p, PBR -0.15)
> → 4.2 + 3.0 + 1.5 = **8.7점** / 30점

**개선 점수 원칙:**
- 상승만 반영 (하락 시 0점, 감점 없음)
- 품질 점수에서 이미 현재 수준 반영됨 → 개선은 "추세"만 평가

##### 점수 계산 설계 원칙

1. **선형 보간 + 상한선**: 극단적인 값(ROE 50%)이 점수를 왜곡하지 않도록 상한선 설정
2. **음수 방지**: PBR 3.0처럼 고평가 종목도 0점이지 마이너스는 아님
3. **업종 상대 비교 (PER)**: 바이오(고PER)와 금융(저PER)을 같은 기준으로 비교하면 불공평 → 업종 평균 대비 비율 사용

##### 종합 예시: 삼성전자

```
품질: 40.25점 + 밸류: 8.8점 + 개선: 8.7점 = 57.75점 / 100점
```

#### 3단계 — 결과 출력

```
종합 점수 상위 N개 → 중앙 패널에 표시
```

### 3-3. 정렬 방식

| 정렬 기준 | 기본값 |
|----------|--------|
| 종합 점수순 | ✅ 기본 |
| ROE 높은순 | 선택 가능 |
| PER 낮은순 | 선택 가능 |
| PBR 낮은순 | 선택 가능 |
| 시가총액 높은순 | 선택 가능 |

### 3-4. 중앙 패널: 종목 리스트

각 종목 카드: `종목명 / PER / PBR / ROE / 종합점수`

### 설계 원칙

- DB에는 **원본 지표값만** 저장 (ROE, PBR, PER, 부채비율 등)
- 점수 계산 로직은 **별도 모듈**로 분리
- 필터 기준값은 **설정으로 관리** → 나중에 코드 수정 없이 변경 가능
- 필터는 단순 DB 조회 조건 (WHERE 절)일 뿐 → 별도 로직 불필요

## 4. 종목 상세 (우측 패널)

**컨셉:** 개별 종목의 재무 데이터와 품질 점수를 한눈에 파악하는 화면
→ 중앙 패널에서 종목 클릭 시 우측 패널에 표시

### 4-1. 기본 정보

```
종목명 / 종목코드 / 시장(KOSPI·KOSDAQ) / 업종 / 현재가 / 등락률
```

### 4-2. 종합 품질 점수

- 수익성(50%) / 밸류에이션(20%) / 개선(30%)
- 스크리너 모드와 **동일한 점수 재활용** → 추가 계산 불필요

### 4-3. 핵심 지표 카드 (최신 연도 기준)

| 지표 | 설명 |
|------|------|
| ROE | 자기자본이익률 |
| ROA | 총자산이익률 |
| PER | 주가수익비율 |
| PBR | 주가순자산비율 |
| 부채비율 | 재무 안전성 |
| 배당수익률 | 배당 매력도 |

### 4-4. 재무 추이 차트 (3년: 당기/전기/전전기)

| 차트 | 항목 |
|------|------|
| 차트 A | ROE / ROA 추이 |
| 차트 B | 매출액 / 영업이익 추이 |
| 차트 C | 부채비율 추이 |

### 4-5. 동종업계 비교 (MVP 포함)

```
업종 평균 대비 ROE / PER / PBR 비교
예: 삼성전자 ROE 18.3% vs 반도체 업종 평균 12.1%
```

### 설계 원칙

- 모든 수치는 DB의 **원본값** 그대로 표시
- 점수는 스크리너와 **공유** (별도 계산 없음)
- 동종업계 평균은 **업종 코드 기준**으로 같은 업종 종목들의 평균값 계산

## 5. 시야 AI (우측 패널 탭)

**컨셉:** DB 데이터 + 웹검색 기반으로 사용자 질문에 답하는 AI 분석 어시스턴트
→ 종목 상세 화면에서 "시야 AI" 탭 클릭 시 활성화

### 5-1. 답변 범위

| 유형 | 예시 |
|------|------|
| 특정 종목 분석 | "삼성전자 지금 살 만한가요?" |
| 종목 간 비교 | "삼성전자 vs SK하이닉스 비교해줘" |
| 종목 추천 질문 | "지금 어떤 종목이 좋아?" |
| 투자 일반 질문 | "PBR이 뭐야?", "가치투자란?" |

### 5-2. 작동 방식

```
사용자 질문
    ↓
① 우리 DB에서 관련 종목 데이터 조회 (ROE, PBR, PER 등)
② 웹검색으로 최신 뉴스/공시 수집
③ Claude API에 [데이터 + 질문] 전달
④ 시야가 데이터 기반 답변 생성
```

### 5-3. 답변 구성

```
본문 답변 (자연어)
+ 핵심 강점 카드
+ 주요 리스크 카드
```

### 5-4. AI 모델

- **Claude API** 사용
- 모델: claude-sonnet (claude-haiku 대비 응답 품질 우선)

### 5-5. 면책 문구 (필수)

```
"이 분석은 참고용이며 투자 결정은 본인 판단으로 하세요."
```

### 설계 원칙

- DB 데이터를 컨텍스트로 Claude에 전달 → 할루시네이션 방지
- 웹검색은 최신 공시/뉴스가 있을 때만 보완적으로 활용
- 투자 권유가 아닌 **데이터 기반 분석** 입장 유지

## 6. 공시사항 (우측 패널 탭)

**컨셉:** DART 공시 목록을 DB에 수집하여 전체 시장 공시를 빠르게 조회하는 화면
→ Claude API 비용 없이 DB 조회만으로 동작

### 6-1. 위치 및 UI

우측 패널 탭: **종목 상세 | 시야 AI | 공시사항**

- 종목 미선택 시: 공시사항 탭만 표시 (기본 활성화)
- 종목 선택 시: 3개 탭 모두 접근 가능

### 6-2. 표시 요소

| 요소 | 설명 |
|------|------|
| 날짜 선택 | date picker, 기본값 오늘 |
| 검색창 | 기업명 또는 공시제목 필터링 |
| 공시 목록 | 기업명 / 공시제목 / 제출인 |
| 클릭 시 | DART 원문 링크로 새 탭 열기 |

### 6-3. 데이터 수집

| 항목 | 내용 |
|------|------|
| 데이터 소스 | DART OpenAPI (`OpenDartReader.list()`) |
| 수집 주기 | 장중 09:00~18:00, 1시간 간격 (월~금) |
| 수집 방식 | GitHub Actions 스케줄 |
| 저장 | `disclosures` 테이블, `rcept_no` 기준 UPSERT |
| 범위 | 전체 시장 (종목 무관) |
| 비용 | 무료 (DART API 일 10,000건 제한) |

### 6-4. DB 테이블

```
disclosures
├── rcept_no (UNIQUE)    -- DART 접수번호
├── corp_code            -- DART 기업코드
├── stock_code           -- 종목코드 (nullable)
├── corp_name            -- 기업명
├── report_name          -- 공시 제목
├── rcept_date           -- 접수일
├── report_type          -- 보고서 유형
├── flr_name             -- 제출인
├── dart_url             -- DART 원문 링크
└── collected_at         -- 수집 시각
```

### 설계 원칙

- Claude API 비용 없이 DB 조회만으로 동작
- DART API 무료 데이터만 활용
- 전체 시장 공시 목록을 보여주고, 검색으로 특정 종목 필터링
- 공시 원문은 DART 사이트로 직접 연결
