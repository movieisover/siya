## 0. 한 줄 요약

`financials` 분기행이 **2025년부터만** 있다. **2023 Q1~Q3, 2024 Q1~Q3** 를 같은 방식으로 백필해 달라.
그래야 TTM의 '전년 동기' 축이 생겨 Piotroski F-score가 온전해진다.

---

## 1. 왜 필요한가 — 지금 무엇이 깨져 있나

시야트레이더의 1순위 팩터(가치×수익성) 선정 로직을 돌린 결과, **Piotroski 9항목 중 3개가
전 종목 계산 불가**로 나왔다.

| 항목 | 필요한 값 | 상태 |
|---|---|---|
| ③ ΔROA | 전년 TTM 순이익 | ✗ |
| ⑧ Δ매출총이익률 | 전년 TTM 매출총이익·매출 | ✗ |
| ⑨ Δ자산회전 | 전년 TTM 매출 | ✗ |

전년 TTM = `FY(전전년) − 전전년 동기 누적 + 전년 동기 누적` 이다.
현재 기준(2026Q2)에서는 `FY2024 − 2024Q2누적 + 2025Q2누적` 인데, **2024 분기행이 0건**이다.

### 진단 결과 (`siya-trader/selection/diag_fscore.py`, 2026-08-25)

```
fiscal_quarter    FY    Q1    Q2    Q3
fiscal_year
2023            2429     0     0     0
2024            2562     0     0     0      <-- 여기가 비어 있다
2025            2612  2546  2592  2582
2026               0  2565  2540

당해 TTM(FY2025 - 2025Q2 + 2026Q2) 성립 : 2,520종목
전년 TTM(FY2024 - 2024Q2 + 2025Q2) 성립 :     0종목
```

계정 커버리지는 전 기간 고르다(gross_profit 89~92%, cfo 99.8%+). **데이터 품질이 아니라 기간 부재**다.

### 그래서 생긴 왜곡

F-score가 사실상 **6점 만점**이 되는데 컷은 6점이라, "6개 항목 전부 만점"을 요구하게 됐다.
전체 유니버스 607종목 중 22종목만 통과했고, 최종 20종목의 F가 전부 6.00으로 붙어
**순위합(매직포뮬러) 정렬이 사실상 무력화**됐다. 선정 로직이 의도대로 작동하지 않는다.

## 2. 원인 — 수집 범위가 최근 2개 연도로 하드코딩돼 있다

`src/data/collectors/collect_quarterly.py`:

```python
# 최근 2개 연도 (올해 최신 분기 + 작년 동기). TTM 공식에 필요한 최소 범위.
_NOW = datetime.today()
QUARTER_YEARS = [_NOW.year, _NOW.year - 1]
```

"TTM 1개를 계산하는 데 필요한 최소 범위"로는 정확한 설계다. 다만 **TTM 두 개(당해·전년)를
비교**하려면 3개 연도가 필요하다. DART에는 2023·2024 분기 보고서가 그대로 있으므로
수집 범위만 넓히면 된다.

## 3. 요청 사항

### 3-1. 대상

| 연도 | 분기 | 보고서 코드 |
|---|---|---|
| 2023 | Q1, Q2, Q3 | 11013, 11012, 11014 |
| 2024 | Q1, Q2, Q3 | 11013, 11012, 11014 |

- 저장 형식·단위·컬럼 전부 **기존 분기행과 동일**(백만원, 누적 `thstrm_add_amount`, `source='dart_q'`).
- **B-1 확장 6컬럼(`cost_of_sales`, `gross_profit`, `cash_and_equiv`, `current_assets`,
  `current_liabilities`, `cfo`) 포함** — 이게 빠지면 ⑧이 다시 죽는다.
- 스키마 변경 없음. `UNIQUE(stock_code, fiscal_year, fiscal_quarter)` 그대로 upsert.

### 3-2. 코드에서 손봐야 할 곳 (판단은 시야에 맡김)

1. **`QUARTER_YEARS` 파라미터화** — 예: `--years 2023 2024`. 기본값은 현행 유지해 정기 수집 동작 불변.
2. **`--resume` 재개 판정** — 현재는 "이번 시즌 최신 분기 행 유무"로 판정한다(2026-08 버그 수정 이력).
   과거 연도 백필에서는 그 기준이 안 맞으니, **대상 (연도, 분기) 조합별 행 존재 여부**로 판정해야
   한도 분할 이어받기가 정확하다.
3. `REPRT_FILING_CUTOFF` 는 과거 연도라 전부 통과 — 수정 불필요.

### 3-3. 콜 예산과 절감 제안

`collect_quarterly.py` 주석의 실측 기준(4조합 ≈ 15,000콜)으로 환산하면 조합당 약 3,750콜이다.

| 항목 | 추정 |
|---|---|
| 6조합 전종목 | 현실 ~22,500콜 (최선 ~16,500 / 최악 ~33,000) |
| 일 가드(`DART_DAILY_LIMIT=8500`) | **3~4일 분할** |

**절감 제안**: 그 해에 상장돼 있지 않았던 종목은 조회해도 빈손이다. `financials` 의 FY 행을
프록시로 쓰면 헛콜을 줄일 수 있다.

- 2023 분기 → **FY2023 행이 있는 2,429종목**만 조회
- 2024 분기 → **FY2024 행이 있는 2,562종목**만 조회

전종목(2,773) 대비 각각 12%·8% 절감이라 크진 않지만, 한도 분할 일수를 하루 줄일 수 있다.
판단은 시야에 맡긴다.

## 4. 백필이 주는 부수 효과 (F-score 말고도)

1. **백테스트 시간축 확장** — `siya-trader/CLAUDE.md` §15에 "남은 병목은 FY 게이팅(2024-04~)"으로
   적혀 있다. 분기 공시가 생기면 재무 가용 시점이 2023 중반부터로 앞당겨진다.
2. **과거 시점 재현 가능** — `run_selection.py --as-of 2024-11-20` 같은 분기 리밸런싱 시점별
   선정 재현이 가능해진다(현재는 전년 TTM이 없어 과거 시점에서 F가 더 크게 망가진다).
3. **`ttm_earnings` 시계열화** — 지금은 최신 1개 시점만 계산 가능하다.

## 5. 회신에 담아줬으면 하는 것

1. **커버리지**: 2023·2024 각 분기별 행 수 + 6컬럼 NOT NULL 비율 (B-1 회신 §2 형식 그대로면 충분)
2. **누적 기준 동일 확인**: 2023·2024도 `thstrm_add_amount` 누적으로 들어갔는지
   (Q1=3M / Q2=6M / Q3=9M). 기간 정의가 섞이면 TTM 공식이 조용히 틀린다.
3. **계정 태그 변화 유무**: 과거 보고서에서 `ifrs-full_GrossProfit` 직접계정 폴백률이
   최근과 다른지. B-1에서는 폴백 0건이었다.
4. **정정공시 취급**: DART 조회는 현시점 기준 최신(정정 반영) 값을 준다. 즉 백필된 과거 분기는
   **당시 공시된 원본이 아니라 정정 후 값**일 수 있다. 이건 과거 시점 재현에서 미세한 룩어헤드가
   되므로, 시야가 이를 구분할 방법(정정 여부 플래그 등)이 있는지, 없다면 "없다"고만 알려주면
   시야트레이더가 리포트에 한계로 명시하겠다.
5. **skip 종목 수와 사유** (B-1의 158종목 skip 같은 꼬리)

## 7. 시야트레이더 쪽 대비 상태

백필을 기다리는 동안 선정 로직이 멈추지 않도록 **폴백 체인**을 넣어 뒀다.

```
Δ항목(③⑧⑨) 비교 기준:
    전년 TTM (원설계)  →  없으면 FY2025 vs FY2024 (Piotroski 원전 정의)  →  계산불가
```

종목별로 `delta_basis` 태그가 붙고 리포트에 분포가 찍힌다.
**2023·2024 분기가 들어오면 코드 수정 없이 `delta_basis='ttm'` 으로 자동 승급**되므로,
백필 완료 후에는 그냥 `run_selection.py` 를 다시 돌리면 된다.
