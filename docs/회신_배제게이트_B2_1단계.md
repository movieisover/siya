## 3. §3-2 답 — 감사의견, DART 정형 API로 **받을 수 있다**

첨부 감사보고서 파싱은 필요 없다. 정기보고서 주요정보 API에 전용 엔드포인트가 있다.

```
GET https://opendart.fss.or.kr/api/accnutAdtorNmNdAdtOpinion.json
    ?crtfc_key=...&corp_code=...&bsns_year=2025&reprt_code=11011
```

응답 필드:

| 필드 | 내용 |
|---|---|
| `adt_opinion` | `적정의견` / 한정 / 부적정 / 의견거절 |
| `emphs_matter` | 강조사항 — **계속기업 불확실성이 여기 들어온다** |
| `adtor` | 감사인 (예: 삼정회계법인) |
| `core_adt_matter` | 핵심감사사항 |
| `stlm_dt` | 결산일 |

### 그런데 실익은 0이었다

684종목 전부 FY2025 감사의견을 조회했다(684콜, 오류 0).

- **비적정(한정·부적정·의견거절): 0종목**
- 적정의견: 663
- 의견 필드 빈값: 21

당연한 결과다. 비적정을 받으면 즉시 거래정지·상폐 절차로 들어가므로 **60일 ADV 10억을
통과할 수가 없다.** 유동성 게이트가 이미 감사의견 게이트의 대리 역할을 하고 있다.

대신 건질 게 하나 있었다 — **계속기업 불확실성 강조사항**(감사의견은 적정이지만 감사인이
경고를 단 경우) **3종목**:

- 011230 삼화전자
- 215790 이노인스트루먼트 ← 관리종목과 중복
- 376900 로킷헬스케어

### 구현 시 주의 2가지

1. **연결/별도 행이 중복으로 온다.** 같은 `rcept_no`로 당기·전기 × 연결·별도가 섞여 나오고
   `fs_div` 같은 구분 필드가 없다. `bsns_year`에 `(당기)`가 들어간 행만 취하고 dedupe해야 한다.
2. **의견 필드가 빈값인 종목이 684 중 21개.** 현대차·대한항공·한국콜마·롯데웰푸드 등
   대형주가 포함돼 있다 — **공시 서식 편차이지 부실 신호가 아니다.** 빈값을 위험으로 처리하면
   안 된다.

## 4. 소스 판단 (§1-2 "어느 쪽이 안정적인지 시야가 판단해 달라")

### 관리종목·거래정지 → **KIS API 권장** ✅

`/uapi/domestic-stock/v1/quotations/inquire-price` (FHKST01010100) 응답에 이미 들어있다.

| 필드 | 의미 |
|---|---|
| `mang_issu_cls_code` | 관리종목 Y/N |
| `iscd_stat_cls_code` | 51=관리 / 52=투자위험 / 53=투자경고 / 58=**거래정지** / 55=신용가능 |
| `mrkt_warn_cls_code` | 00=없음 / 01=주의 / 02=경고 / 03=위험 |
| `sltr_yn` | 정리매매 여부 |

- 이미 인증·유량제어(초당 3건)가 붙어 있고 `daily_update`가 매일 도는 경로다.
- **스크래핑 아님** — 파싱 깨질 위험 없음.
- **교차검증 통과**: 네이버 금융 관리종목 목록(전체 167종목)과 684 교집합을 대조한 결과
  KIS `mang_issu_cls_code=Y` 5종목과 **완전 일치, 불일치 0건.**
- 비용: 684종목 × 0.4s ≈ 5분. 전종목(2,773) 기준 ≈ 19분.

### 투자주의환기 → **KIND 스크래핑밖에 없다** ⚠️

- KIS에 해당 필드가 없다. `invt_caful_yn`은 다른 개념이고 전 종목 N이었다.
- 경로: `https://kind.krx.co.kr/investwarn/hwangiissue.do` POST
  (`method=searchHwangiIssueSub`, EUC-KR, 현재 **91종목**, 지정일·사유 포함)
- **약점: 종목코드가 없다.** 종목명으로 조인해야 하는데, 91개 중 6개가 우리 `stocks`의
  종목명과 불일치했다(개명 종목 — 졸스·아이오케이이엔엠·아고스·루트K·지구홀딩스·성원에너텍).
  FDR로 코드를 확인해보니 6개 모두 684 밖이라 **이번 숫자에는 영향 없다.** 다만 이름 조인은
  구조적으로 취약하므로, 채택한다면 조인 실패 건을 로그로 남기고 감시해야 한다.
- 참고: 이 목록의 사유 텍스트에 `내부회계관리제도 비적정`, `반기 검토(감사)의견 비적정`,
  `계속기업 불확실성에 의한 한정` 같은 회계 신호가 같이 들어온다.

## 5. 2단계 제안 — 실익 순으로 재배열

측정 결과를 보고 나니 핸드오프의 우선순위(관리종목 → 감사의견)와 순서가 달라졌다.

### ① 거래정지 + 관리종목 — **권장, 최우선**

- KIS 필드 2개(`mang_issu_cls_code`, `iscd_stat_cls_code`)를 `daily_update`에 얹는다.
- 실익: 684 기준 8종목(관리 5 + 거래정지 3 추가). **거래정지는 페이퍼가 아니라 실매매에서
  주문 자체가 안 나가므로 성격이 다르다** — 팩터 품질 문제가 아니라 체결 가능성 문제다.
- 비용: 매일 도는 배치에 필드 추가 수준. 추가 API 호출 없이 기존 조회 응답에서 뽑으면 된다.

### ② 투자주의환기 — 권장하되 ①보다 뒤

- 실익 3종목(313 기준 1종목). KIND 스크래핑 + 이름 조인 취약성을 감수해야 한다.
- 주 1회 갱신으로 충분하다(연 1회 정기 지정 + 수시 지정).

### ③ 투자경고 — **판단을 요청한다**

- 684 중 13종목, 313 중 6종목으로 **관리종목보다 많다.**
- 다만 성격이 다르다. 투자경고는 부실이 아니라 **단기 급등에 대한 시장경보**이고,
  지정되면 매수 시 위탁증거금 100%가 요구되며 요건 충족 시 하루 매매거래정지가 걸린다.
- 가치 팩터가 급등주를 뽑는 건 드문데 6종목이 실제로 걸렸다는 점이 오히려 특이하다.
  **"감사 가능한 배제 게이트"의 취지(부실 배제)에는 안 맞지만, 체결·비용 관점에서는
  걸러야 할 수도 있다.** 시야트레이더 쪽 판단이 필요하다.

### ④ 감사의견 — **미루거나 축소 권장**

- 비적정 실익 0으로 측정됐다. 유동성 게이트가 대리 역할을 한다.
- 넣는다면 `adt_opinion` 배제가 아니라 **`emphs_matter`의 계속기업 불확실성**만 뽑는 형태로,
  연 1회 사업보고서 시즌(3~4월)에 돌리는 게 비용 대비 낫다. 실익 3종목.

## 6. §2 요청 형식에 대한 답 — 지정일/해제일

- **관리종목**: KIND 이력 페이지(`adminissue.do`)에 지정·해제 이벤트와 날짜가 있다. 다만
  종목코드가 없어 이름 조인이 필요하고, 어디까지 소급되는지는 확인하지 않았다.
- **투자주의환기**: 현재 목록에 지정일이 같이 나온다(위 §2 표).
- **거래정지·관리종목(KIS)**: **현재 스냅샷만 나온다. 지정일 없음.**

> ⚠️ **`--as-of` 과거 재현에 대한 솔직한 답**: 어느 소스든 **과거 임의 시점의 상태를
> 소급 복원할 방법이 없다.** 지금부터 매일 스냅샷을 쌓아야 미래의 과거 재현이 가능해진다.
> 따라서 핸드오프 §2에 적어둔 대로, **당분간은 현재 스냅샷을 쓰되 시야트레이더 리포트에
> "과거 재현에는 적용하지 않음"으로 명시**하는 쪽이 맞다. 2단계에 착수하면 그날부터
> 이력이 쌓이기 시작한다 — 그것만으로도 시작할 이유는 된다.
